# CTX-58: Dev codesearch ↔ backend worker JWT / env parity is fragile (401 on resolve-ref, noisy purge, index edge cases)

## **Problem**

Host dev runs the **API + OpenWorkflow worker on the host** and **codesearch in Docker** (`scripts/codesearch-docker-dev.sh`). Both must verify/sign the same upstream JWTs (`apps/backend/src/auth/upstreamJwt.ts`), but they **do not share a single, explicit contract** for which env vars define `iss`, `aud`, and `AUTH_SECRET`.

That produced several confusing failures:

1. `resolve-ref` → 401 Unauthorized
   Ingestion calls codesearch (`POST /{repoId}/resolve-ref`) with a service JWT. Verification failed while the repo row existed in Postgres. Root causes included:
   * **Issuer mismatch**: signing uses `AUTH_ISSUER ?? AUTH_BASE_URL ?? "ctxpipe-backend"`, but codesearch previously verified with `AUTH_ISSUER` only (often unset), while the worker used `AUTH_BASE_URL` from portless (`scripts/dev-apps.sh` exports `AUTH_BASE_URL` before Turbo).
   * **Shell vs file ordering**: sourcing `apps/backend/.env` in the docker script could **overwrite** portless `AUTH_BASE_URL` with a stale default from `.env`.
   * **Partial env into Docker**: only some JWT-related vars were passed through; audience/issuer drift vs worker.
   * **Worker dotenv order**: worker loaded `.env.local` then `.env` without override, which could diverge from “local overrides base” and from what Docker sourced.
2. `POST …/index` → 404 while `resolve-ref` succeeded
   Index requires a `repository_checkouts` row (Zoekt id); resolve-ref only needs `repositories`. Missing checkout → same generic 404 message (“Repository not found or access denied”).
3. **DELETE repo → ERROR log on codesearch purge 404** while HTTP **204**
   Purge is best-effort; 404 means “nothing on disk to purge” but was logged as an error.
4. **Operational noise**
   Multiple overlapping env sources (portless exports, `.env`, `.env.local`, Docker `-e`, Turbo/concurrently) make it easy for **two processes to disagree** without it being obvious in logs.

## **Suggested solutions**

**A. Short term (done or partially done in branch — worth review)**

* **Single issuer rule** in codesearch: verify with the **same** fallback chain as signing (`AUTH_ISSUER ?? AUTH_BASE_URL ?? "ctxpipe-backend"`).
* **Preserve portless** `AUTH_BASE_URL` when sourcing backend `.env` files before `docker run`, and **forward** `AUTH_BASE_URL` into the container.
* **Align dotenv** in `openworkflow.config.ts`: load `.env` then `.env.local` with `override: true` on local.
* **Merge** `.env` + `.env.local` in `codesearch-docker-dev.sh` (local wins) so Docker gets the same JWT-related vars as the worker.
* **Index path**: ensure default checkout exists when repo row exists but checkout is missing (`ensureIndexableRepository`).
* **Purge**: treat codesearch purge **404** as idempotent success (log info, not error).

**B. Medium term (recommended for Jakub / platform)**

* **One “contract” document** (short ADR or `AGENTS.md` section): list **exact** env vars that must match between worker, backend, and codesearch; **no** implicit reliance on “whatever portless exported”.
* **Smoke test** in CI or a dev script: sign a JWT with backend helpers and assert codesearch verifies it (or hit `resolve-ref` with a test token against a test container).
* **Stricter logging** on 401 from codesearch: optional debug line (dev only) indicating *which* claim failed (without logging secrets).

**C. Longer term**

* **Shared package** for “upstream JWT config” (issuer/audience resolution) imported by backend and codesearch, or a tiny JSON schema checked at startup.
* Consider **running codesearch on the host** in dev (optional profile) to remove Docker env bridging — trade-offs: Zoekt/cgc setup vs simpler env.
