# CTX-32: Allow the user to install the MCP files into already ingested repos, if missed

If the user connected a repo and chose to install the MCP manually, we should allow the user to change this within the repo-management UI in the app (not in the onboarding flow), accessed via the menu in the /repositories URL.

It should be something like:

* User goes to repository page
* User clicks 'triple dot' button icons
* User clicks 'Select repositories' link
* User clicks 'Install MCP in selected repos' button (would this be a good CTA and UX?)
* User presented with model like the onboarding one, to choose agents and then see the diffs before clicking 'raise PRs' and see the associated URLs

## What I shipped (CTX-32)

* **Repositories** → header **⋯** menu → new **Install MCP via PRs** (under *GitHub integration*, next to *Select repositories*). It only enables when a GitHub App installation exists.
* Opens a **wide modal** with the same **agents → repos → diffs → Raise pull requests → PR links** flow as onboarding’s “Open PRs for me” path.
* **Already-ingested GitHub repos** are **pre-ticked** by parsing `owner/repo` from each indexed repo’s `gitUrl` (HTTPS or `git@github.com:…`). Users can add/remove repos from the installation list before previewing.

Implementation: extracted `McpConfigPrWizard` from `McpOnboardingSlide`, extended `Modal` with optional `size="wide"`, added `githubRepoFullNameFromGitUrl` in `github-web-url.ts`.

**PR:** [https://github.com/ctxpipe-ai/ctxpipe/pull/86](<https://github.com/ctxpipe-ai/ctxpipe/pull/86>) (draft)

## On your CTA question

**“Install MCP in selected repos”** is slightly misleading: nothing is installed *into ctx|*—you’re opening **GitHub PRs** that add/merge JSON on the default branch. I used **“Install MCP via PRs”** so the mechanism is obvious and expectations match the backend (`mcp-config-preview` / `mcp-config-prs`). If you prefer the softer onboarding wording, rename in the menu only; behaviour stays the same.

**Assumption to watch:** pre-selection only covers [**github.com**](<http://github.com>) remotes we can normalise. Self-hosted Git or non-standard URLs won’t pre-check; those users still pick repos manually—which is correct unless you store `full_name` on the repository row.

**Tests run:** `pnpm --filter @ctxpipe/ui test` passed; Biome was run clean on the touched files only (full UI `check` already had many pre-existing issues).
