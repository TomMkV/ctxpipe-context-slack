# CTX-85: Onboarding for knowledge graph page

The knowledge graph page can be overwhelming for users.

When they first arrive, I think some onboarding should be presented to them to guide them on what to do. And this should include a link to the docs (currently being worked on).

I'm not sure if this should be an animation in a modal, showing the page being used, or something else. 

Maybe the page is self explanatory!?

I'd like an assessment and some suggestions of how to approach onboarding of the knowledge graph page, and note that if an animation is to be done, I will handle that via Unicorn Studio.

## Triple-check: is it worth the space, code, and friction?

**Honest read:** partly yes, partly no — so the right move is to **keep the feature but shrink the payload**.

What **new users genuinely do not infer** from a force-directed blob:

* **Pan/zoom** is on the **background** (many people try to drag nodes first).
* **Selection** opens a **drawer** with claims/neighbours/confidence — the canvas alone does not say “inspector”.
* **Search vs node kinds** live in **different corners**; without a pointer, people treat the legend as decorative.
* `?node=` deep links are **invisible** unless you know to look at the URL.

That is **non-trivial** product knowledge. A single link to the guide does **not** replace those affordances on first load, because the problem is **spatial discovery**, not conceptual depth.

**Where it was too heavy:** three bullets plus a long intro duplicated what the **dedicated doc** now explains (activity sparkline, truncation, etc.). That inflated **vertical space** and **reading friction** without adding much beyond the doc.

**Friction trade-off:** first visit shows a panel once per org (localStorage); after dismiss, only a small **Tips** control remains. That is a **reasonable** cost if the copy stays **tight**.

---

## What I changed just now (fit + style)

1. **Tighter copy:** one short paragraph (pan / zoom / drawer) plus **two** bullets (narrow + share). Removed the third bullet that mostly repeated “search” as its own line.
2. **Visual alignment** with the rest of the knowledge graph UI (`MapControlButton`, `FloatingPanel`): `rounded-none`, `border-zinc-800/95`, `bg-zinc-950/90`, `shadow-xl shadow-black/40`, `backdrop-blur-md` on the **X**, **Close**, **Full guide** link, and **Tips**; **8×8** close control to match map controls.
3. **No double shadow:** dropped extra `shadow-*` / `backdrop-blur` from the callout’s outer `FloatingPanel` class so it does not stack on top of the base panel chrome.

Pushed on `cursor/knowledge-graph-onboarding-c736` (latest commit: `refactor(ui): tighten knowledge graph tips copy and match map chrome`). Your PR branch should show that when you pull.

I did not go that far yet because the two bullets still earn their keep for **where** to look on the screen.

### Panel review (position, dismiss, clarity)

**Position**

* The tips block stays in the **left column** under the title and metric chips (same mental model as before: “chrome on the left”).
* `z-30` on that column so the panel stays **clickable above the graph** (canvas was effectively winning pointer events at `z-10`).
* With the **centred search** on small screens, the tips block gets `max-sm:mt-10` when the graph is visible so it **sits lower** and is less likely to sit under the search bar. On wide layouts the search is centred and the left column is clear anyway.

**Dismiss**

* **Large X** (`min-h-9 min-w-9`) with hover border/background so it is easy to hit on touch and obvious.
* A proper `Close` button (bordered, full tap target) beside the docs link — no “only a faint text link” dismissal path.

**Clarity**

* Title **“Quick tips”** plus a **one-line summary** of the main interaction (pan/zoom → select node → inspector).
* Bullets now **name real UI locations** (search top centre, kinds top right, `?node=` in the address bar) so they match what people see.
* Docs control reads **“Knowledge graph guide”** with **“Opens in a new tab”** so expectations are explicit.

**Escape**

* I **did not** add global **Esc-to-close** for the tips: the search field already uses **Esc to clear**, and binding Esc on `window` would make that ambiguous or wrong when focus is in search. Dismissal is intentionally **X + Close** only.

### 2026-04-23T12:00:01.265Z · cursor

[**Knowledge graph onboarding assessment**](<https://www.cursor.com/agents/bc-76402507-b4fb-4218-ab9a-8106e4dac736>)

## Assessment

The knowledge graph page is **not** self-explanatory for most people. The UI already exposes useful affordances (search bar, node kinds, fit/refresh, activity sparkline, node drawer), but **nothing tells you that pan/zoom and clicking nodes are the main interaction model**, that **kinds are toggles**, or that `?node=` mirrors selection for sharing. For first-time visitors—especially with a large force-directed blob—the default reaction is often “pretty, but what do I do?” That is a reasonable product gap, not user error.

**Counterpoint:** power users who live in graph tools may infer behaviour quickly; **over**-onboarding (blocking modals, forced tours) will annoy them. The design needs a **light default** plus a **way back** to help without resetting local state.

## Suggested approaches (and trade-offs)

| Approach | Pros | Cons |
| -- | -- | -- |
| **Inline callout / coach marks** (dismissible) | Fast to ship, non-blocking, works with your existing `FloatingPanel` chrome | Less “wow” than motion |
| **“Tips” entry point** after dismiss | Fixes the “I dismissed it and forgot” problem | Extra UI clutter if not subtle |
| **Modal + animation (e.g. Unicorn)** | Strong narrative, good for complex flows | Blocks the canvas; harder to maintain; you already flagged handling motion yourself |
| **Empty state only** | Very light | Misses users who *have* data but are still lost |

**Recommendation:** start with **dismissible inline guidance + docs link + “Tips” to reopen** (what ships below). If you add Unicorn later, treat it as **optional** inside the callout or a one-time modal **without** removing the short bullet copy (motion should reinforce text, not replace it).
