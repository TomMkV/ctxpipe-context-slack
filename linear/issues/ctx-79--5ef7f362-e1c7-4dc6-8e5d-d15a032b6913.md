# CTX-79: Knowledge graph compression for larger graphs

We had compression but it caused issues during deployment, so it was removed.

I want to ensure we re-apply this - but want to et the deployment done.

For later, three drop-in options:

* Manual Bun gzip (simplest, works today):

```typescript
  const body = JSON.stringify(snapshot)                                                                                                                                           
  const accept = c.req.header("accept-encoding") ?? ""
  if (accept.includes("gzip") && body.length > 10_000) {                                                                                                                          
    return new Response(Bun.gzipSync(body), {                                                                                                                                     
      headers: { "content-type": "application/json", "content-encoding": "gzip" },                                                                                                
    })                                                                                                                                                                            
  }                                                                                                                                                                               
  return c.json(snapshot, 200)  
```

* Upgrade Bun — CompressionStream was added in Bun 1.1.x; your Alpine image build may lag. Worth testing oven/bun:1.3-alpine locally.
* Pagination / streaming — split nodes + edges into separate endpoints or NDJSON stream. Bigger refactor; only if the snapshot concept itself stops scaling.
