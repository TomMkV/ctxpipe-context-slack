# CTX-125: Railway is not duplicating production environment on PR deployment correctly

[https://github.com/ctxpipe-ai/ctxpipe/actions/runs/26554555513/job/78226061903#step:9:33](<https://github.com/ctxpipe-ai/ctxpipe/actions/runs/26554555513/job/78226061903#step:9:33>)

As you can see from the github actions run above, first try created the environment but then failed to duplicate from production therefore second try, sees that environment is already created so doesn't try to duplicate from production again. This ends up leaving the pr environment in a bad state.

Acceptance criteria:

* To avoid this issue, if railway environment new fails, we should use railway environment delete to clean it up so retry can start with a clean slate
* Caveat is that railway api fails with `An environment with that name already exists` after environment has already been delete - likely due to eventual consistency so after deleting, we should wait for 5 minutes before letting retry run

## Problem

When `railway environment new --duplicate production` fails after creating a partial PR environment, the retry step sees the env as existing and skips duplication — leaving preview environments broken. Railway can also return "already exists" for a while after delete due to eventual consistency.

## Solution

### 1\. `scripts/railway-ensure-pr-environment.sh`

| Scenario | Behavior |
| -- | -- |
| Env readable via `environment config` | Skip create |
| Env exists but config unreadable | Paginated GraphQL delete by id → wait **5 minutes** → recreate |
| `environment new` fails | Delete via GraphQL + CLI fallback → wait **5 minutes** → exit 1 for `nick-fields/retry` |

Paginated GraphQL lookup handles environments not on the first API page (a prior failure mode). Even when delete finds nothing (ghost reserved name), the script still waits 5 minutes before exiting so the outer retry can succeed.

### 2\. `.github/workflows/pr-deploy.yaml`

* Replaced inline shell with the new script
* Increased `timeout_minutes` from 5 → **15** (to fit the 5-minute wait)
* Set `retry_wait_seconds: 0` (the script owns the wait)

1. **Retry create up to 5 times inside the script**, with cleanup between attempts.

3. **Wait 30s when nothing can be deleted** — handles ghost names after manual deletes.
4. **Outer retry** increased to 60s wait, 15 min timeout.

[**Railway PR environment duplication**](<https://www.cursor.com/agents/bc-3eff8a61-353d-4f51-ae48-45e36d6c6b3d>)

In Bash, `[[ -n "$ENV_ID" ]]` does **not** check whether something is boolean `true`. It only checks whether the string is **non-empty**.

So if:

```bash
ENV_ID="true"
```

then `[[ -n "$ENV_ID" ]]` is **true**, because `"true"` has 4 characters.

Same for any non-empty value:

```bash
ENV_ID="false"   # still passes -n
ENV_ID="0"       # still passes -n
ENV_ID="abc123"  # still passes -n
```

Only empty/unset fails `-n`:

```bash
ENV_ID=""        # fails -n
unset ENV_ID     # fails -n
```

In our Railway script, `ENV_ID` is set from GraphQL/jq:

```bash
ENV_ID="$(lookup_env_id "$PR_ENV" || true)"
```

So in practice it should be either:

* an actual Railway environment id (a UUID-like string), or
* `""` (empty) if no env was found

It should **not** normally be the literal string `"true"`.

If it somehow were `"true"`, the script would incorrectly think “an environment exists” and go down the “env exists” branch, which could cause wrong behavior.

If you want to test for boolean true specifically, you'd use something like:

```bash
if [[ "$ENV_ID" == "true" ]]; then
  ...
fi
```

But that's not what this script is doing. It's just: “do we have an environment id string?”

[**Railway PR environment duplication**](<https://www.cursor.com/agents/bc-3eff8a61-353d-4f51-ae48-45e36d6c6b3d>)

`if [[ -n "$ENV_ID" ]]` is a Bash test that runs the block only when `ENV_ID` is **non-empty**.

* `[[ ... ]]` — Bash conditional (like `[ ... ]`, but safer for quoting/variables)
* `-n "$ENV_ID"` — true if the string has **length > 0**
* `"$ENV_ID"` — expands the variable; quotes handle empty or whitespace safely

Examples:

```bash
ENV_ID="abc123"
if [[ -n "$ENV_ID" ]]; then
  echo "we found an environment id"
fi
# runs

ENV_ID=""
if [[ -n "$ENV_ID" ]]; then
  echo "we found an environment id"
fi
# does not run
```

In `scripts/railway-ensure-pr-environment.sh`, it means: “if GraphQL found a Railway environment id for this PR name, treat it as existing and decide whether to keep or delete/recreate it.”

The opposite is `-z` (“is empty”):

```bash
if [[ -z "$ENV_ID" ]]; then
  # ENV_ID is empty or unset
fi
```
