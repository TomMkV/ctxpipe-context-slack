## Investigation (CTX-95)

**Primary cause:** The stack traces are unambiguous: Better Stack’s OTLP endpoint is returning **HTTP 402 with** `Message=Quota reached`. That is a **Better Stack account/plan quota** response, not a misconfiguration bug in your application code. The collector marks it as a **permanent** failure (correctly — retrying will not help until quota changes), drops the batch, and logs `Exporting failed. Dropping data` each time.

**Why it feels “huge”:** The default **batch** processor flushes about every **200ms**, so you get many export attempts (and thus many error lines) per minute even for moderate traffic.

**Langfuse warnings** (`Span not found in runMap`) are a **separate** SDK/concurrency concern; they are not what triggers the 402. They may correlate in time with general load but are not the root cause of Better Stack rejecting exports.

**What actually fixes telemetry delivery:** Increase Better Stack quota, cut ingest (sampling, narrower auto-instrumentation, or not sending full APM traces to Better Stack), or stop exporting to Better Stack until billing is sorted.

## What I changed (PR)

Branch `cursor/fix-otel-betterstack-quota-noise-38f7` → **draft PR:** [https://github.com/ctxpipe-ai/ctxpipe/pull/143](<https://github.com/ctxpipe-ai/ctxpipe/pull/143>)

1. `apps/otel-collector/config.yaml` — Dedicated batch processors `batch/betterstack` and `batch/langfuse` with `timeout: 5s` and `send_batch_size: 512` instead of the implicit 200ms default, so you send **fewer HTTP requests** for the same data and get **less Railway log spam** when quota is already blown (each failure is still one log line per batch, but batches are emitted less often).
2. `apps/otel-collector/README.md` — Documents 402 as quota, operator actions, and clarifies Langfuse vs Better Stack.

Docker was not available on this agent VM, so I could not run `otelcol validate` here; the YAML matches the upstream batch processor options from OpenTelemetry docs.

**Skeptical note:** Batching helps **churn and noise**; it does **not** remove the need to fix quota or reduce volume if you care about data actually landing in Better Stack.
