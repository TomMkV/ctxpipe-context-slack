# CTX-102: Add 'copy invite link' to invite page

As some self hosting users may not have an available STMP provider ready, and wish to invite team members, we should offer a 'copy invite link' link/button on the Org team page. This should be in the docs, too. It's both a fall back and simpler UX for smaller teams.

See the attached screenshot from the: org-slug/organization/members page, it should be here.

Also, update the docs pages on orgs + invites to ensure this is captured.

## What we shipped (CTX-102)

**Product behaviour:** On `/$orgSlug/organization/members`, there is now a dedicated strip **between** the members list and pending invitations with **Copy invite link**. It opens a dialog (email, role, optional team when teams are on), calls the same `inviteMember` API as **Invite member**, builds the URL using the **same pattern as** `sendInvitationEmail` in `169:171:apps/backend/src/auth/config.ts` (sign-up + `redirectTo` → accept-invitation + email), copies to the clipboard, and refreshes pending invitations. If that email already has a pending invite, we retry with `resend: true` so you still get a fresh link.

**Why not only patch the library card footer?** `@daveyplate/better-auth-ui` does not expose a slot there without vendoring `OrganizationMembersCard` / `SettingsCardFooter`. `CtxOrganizationView` is a deliberate fork of the library’s `OrganizationView` (noted in-file, pinned to v3.4.0) so the new row stays in the **members column** beside the sidebar. Mobile nav uses a **vaul** drawer (`apps/ui/src/components/ui/drawer.tsx`, dependency added) so we do not rely on non-exported internals from the package.

**Docs:** Updates to [team members](<apps/docs/content/docs/(guide)/managing-organisation/team-members.mdx>), [self-hosting authentication](<apps/docs/content/docs/self-hosting/authentication.mdx>), and the [FAQ](<apps/docs/content/docs/(guide)/resources/faq.mdx>).

**Checks:** `vitest` on `buildOrganizationInviteLink`, and `pnpm --filter @ctxpipe/ui build` succeeded.

**PR:** [https://github.com/ctxpipe-ai/ctxpipe/pull/162](<https://github.com/ctxpipe-ai/ctxpipe/pull/162>) (draft, branch `cursor/copy-invite-link-members-9c85`).

That is slightly different visually but keeps the members card unchanged and avoids a risky visual merge with the library card’s rounded footer; if you want it literally in that footer row, the next step would be vendoring `OrganizationMembersCard` or upstreaming a slot in better-auth-ui.
