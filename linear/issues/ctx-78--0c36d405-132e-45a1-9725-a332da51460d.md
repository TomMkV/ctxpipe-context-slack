# CTX-78: Add 'Add to Cursor' button for MCP

Easy single click button for adding our MCP to Cursor.

![CleanShot 2026-04-21 at 16.15.36.png](ctx-78--0c36d405-132e-45a1-9725-a332da51460d/assets/src-9eb05f05229a--clean-shot-2026-04-21-at-16-15-36.png)

It would sit in our MCP docs page, and on click it would open an active Cursor session and install the MCP.

I don't know enough of how it works (if you have several Cursor sessions open, is it installed in all, and is it auto refreshed?).

And, how does this reconcile with the existing "install MCP via PR" workflow we have? Just a different method of the same thing, or approaching how to MCP is invoked entirely differently?

## Done (CTX-78)

Implemented an **Add to Cursor** control on the MCP docs page and opened **draft PR #127**: [https://github.com/ctxpipe-ai/ctxpipe/pull/127](<https://github.com/ctxpipe-ai/ctxpipe/pull/127>)

### What shipped

* `AddToCursorMcp` (`apps/docs/app/docs/components/add-to-cursor-mcp.tsx`) — builds `https://cursor.com/en/install-mcp?name=ctxpipe&config=<base64>` where `config` is `{"type":"streamable-http","url":"https://app.ctxpipe.ai/mcp?orgSlug=your-org"}`, matching Railway’s documented pattern (their stdio config uses the same `install-mcp` URL shape).
* **MDX wiring** — component registered in `apps/docs/app/docs/[[...slug]]/page.tsx` so `<AddToCursorMcp />` works in content.
* `mcp-docs.mdx` — Cursor section now leads with the button, then the existing manual `.cursor/mcp.json` JSON.

### Your questions from the issue

1. **Several Cursor sessions / refresh** — This is an OS-level deep link into Cursor, not a push to every window. The in-component note spells out the practical limits (handler wins; reload MCP or restart if tools do not appear). I would not claim stronger guarantees without Cursor documenting them.
2. **vs Install MCP via PR** — Same **server URL and transport** in config; **Add to Cursor** only seeds **your** local `mcp.json`. **Install MCP via PR** is for **repo-committed** config so the team gets the same wiring in Git. Different distribution, not a different protocol.
