# CTX-103: Fix styling on connector page

The modal for the connectors (Github + Confluence) have regressed to older styling: rounded corners and circles, instead of right-angle corners and squares.

Additionally, we have two styles for the connector modal: See pic.


It should be like the Github one. Please change the Atlassian one to be consistent - including the hover state.

Here’s what was wrong and what we changed.

The regression sat mainly in **two places**: the wizard **step list** still used **circles** (`rounded-full`, `IconCircleCheckFilled`) and **pill-ish** row hover (`rounded-md`), and the **Atlassian OAuth panel** used a **separate layout** (outline copy button, teal links, zinc chips, separate rounded URL box) instead of the **same pattern** as `GithubSelfHostedCredentialsStep` (shared strip + ghost copy button + primary/emerald hover).

### What I shipped

* `ConfluenceStepper.tsx` — Step markers are **square** (`rounded-none`); done steps use a **square outline +** `IconCheck` instead of filled circles. Interactive rows use `rounded-none` and `hover:bg-foreground/[0.06]` so hover matches ghost-style controls like the GitHub flow. Copy tokens moved to `foreground` / `muted-foreground`.
* `OrgAtlassianOauthPanel.tsx` — Callback URL is the **same grouped strip** as GitHub (`rounded-md` outer — unchanged from GitHub — **square copy control**: ghost + `rounded-none` + primary / emerald hover when copied). Links `text-primary`; scope snippets `rounded-none bg-muted/80`; **Save OAuth app** `rounded-none`.
* `RegisterAtlassianOauthStep.tsx`, `LinkAtlassianStep.tsx`, `AtlassianOauthAppSavedSection.tsx` — Headings/body text aligned with semantic colours; primary/secondary actions `rounded-none` where they mirror GitHub’s Cancel / Install pattern.

**Tests:** `pnpm --filter @ctxpipe/ui test --run src/features/connectors` passes; Biome clean on the touched files.

**Branch / PR:** `cursor/fix-connector-modal-styling-7920` → draft PR [#163](<https://github.com/ctxpipe-ai/ctxpipe/pull/163>).

**Honest caveat:** `TextField` still uses the shared `rounded-lg` input chrome — same as the GitHub modal. If inputs still feel too soft after this pass, the next step is either a connector-only `TextField`/`Input` override or a dedicated `rounded-none` variant on the field component, not another one-off in copy/paste class soup.

---

### Skeptical read (per your preferences)

1. **Assumption:** “Match GitHub” means pixel-parity with `GithubSelfHostedCredentialsStep`. That file still uses `rounded-md` on URL strips; “right-angle everywhere” would conflict unless we change **both** modals.
2. **Counterpoint:** Replacing `role="group"` on the callback strip removed a Biome error but slightly weakens the labelled region versus GitHub’s markup — acceptable because the **copy button keeps explicit** `aria-label`s.
3. **Logic check:** Using `border-border` on standalone OAuth cards may sit differently next to legacy `border-zinc-800` elsewhere on Connectors; worth a quick visual pass on the **non-wizard** connectors page.
4. **Alternative:** A single `ConnectorCopyRow` primitive shared by GitHub + Atlassian would lock parity long-term and avoid drift — out of scope for this bugfix but the cleaner structural answer.

If you want the remaining Forge/sync steps (`InstallForgeStep`, etc.) brought onto the same `border-border` / `rounded-none` panels as well, say so and we can extend the same treatment without touching unrelated chrome.
