## What I did

**CTX-25** is addressed by treating `streamable-http` as the normal transport everywhere we document ctx| MCP, including the **Cursor**, **Claude**, and **Opencode** examples (Opencode still gets `"enabled": true` where that matters). The earlier Linear note about `http` for Claude is **out of date** relative to your 26 March 2026 standard, so the docs now default to `streamable-http` and only mention legacy `http` under **Troubleshooting** (upgrade path), which is more honest than pretending every shipped client already speaks the new type.

Also updated:

* **Quickstart** API-key snippet — added `type`: `streamable-http` so it matches the MCP page.
* **Onboarding** copy-paste JSON in `onboarding.tsx` — same, so the product does not contradict the docs.

**Verification:** `pnpm install` and `pnpm --filter @ctxpipe/docs build` completed successfully.

**PR (draft):** [https://github.com/ctxpipe-ai/ctxpipe/pull/81](<https://github.com/ctxpipe-ai/ctxpipe/pull/81>)

**Assumption to watch:** If a specific Claude or Opencode build still rejects `streamable-http`, users have the troubleshooting path; if we get field reports, we can add a one-line “minimum version” note without reverting the default in the main examples.
