# CTX-66: Add data for creating a dashboard

We could add more columns to the DB for use in a dashboard.

1. Number of MCP calls per team member
2. Most active repo
3. Account activity roll ups
4. etc

---

Analytics & Observability: Gap Analysis

Mapping the dashboard sections we want against what's actually instrumented today. Most gaps come down to missing event streams and persistence — the data models exist, but usage events aren't being captured.

MCP calls, per user / org / client

* What you'd show: Counts, p50/p95 latency, errors
* What's missing: Persistent mcp_tool_calls table; clientId in context; duration/outcome capture

Most-used tools

* What you'd show: Bar chart of tool names
* What's missing: Tool-name + duration is the only thing near-ready — just needs persistence

"Agent references Jira the most"

* What you'd show: External system rollup
* What's missing: No "external system reference" event stream at all. Agent calls to Atlassian/Linear/GitHub aren't logged with a system classifier. Hardest gap.

Most-used repo

* What you'd show: Rank by retrievals
* What's missing: objects / claims exist, but no usage events. Need "this retrieval touched repo X" events in the LangGraph retrieval nodes.

Conversations / cost / tokens

* What you'd show: Tokens by user, cost by org
* What's missing: Nothing in DB. Either persist from Langfuse callbacks or capture at LLM invocation site in LangGraph.

DAU/WAU/MAU

* What you'd show: User activity timeline
* What's missing: No last_active_at on users; session has updatedAt but only bumps on explicit refresh. Cheap to add a user_activity event.

Errors per tool

* What you'd show: Error rate, top failure modes
* What's missing: Same mcp_tool_calls table covers this if we record status + error.

Proposed work

* Create mcp_tool_calls table (covers MCP calls, Most-used tools, Errors per tool)
* Add clientId propagation through MCP request context
* Emit external-system reference events from tool-call classifier
* Emit retrieval-touched-object events from LangGraph retrieval nodes
* Persist token/cost data from Langfuse callbacks or LLM invocation site
* Emit user_activity events; derive DAU/WAU/MAU from those
