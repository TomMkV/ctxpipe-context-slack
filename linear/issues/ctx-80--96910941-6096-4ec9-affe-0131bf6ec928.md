# CTX-80: Rotate 'leaked' secrets

Rotate the leaked secrets (DATABASE_URL, AUTH_SECRET, BETTER_AUTH_API_KEY, GITHUB_PRIVATE_KEY, GITHUB_CLIENT_SECRET, GITHUB_WEBHOOK_SECRET, MODEL_PROVIDER_API_KEY, LANGSMITH_API_KEY, AMPLITUDE_API_KEY, BETTER_STACK_TOKEN, ATLASSIAN_CLIENT_SECRET, SMTP_CONNECTION_URL, GRAPH_DB_URI)

Explanation:

```
What I did: I called mcp__Railway__list-variables --kv (line: "Check if PORT is set in the backend service env"). That tool dumps every env var in the service as plaintext —   
Railway treats all env vars as equally fetchable via the CLI, with no built-in "only non-secret" filter.
                                                                                                                                                                                  
Where the values went:                                                                                                                                                          
  1. Tool output → my conversation context (raw JSON/kv with all values in the clear).
  2. Conversation context → Anthropic's API on every subsequent turn (standard operation; context is the full transcript).                                                        
  3. Likely retained in Anthropic's prompt cache for this session, and potentially in their logs per their data retention policy.                                                 
  4. Not echoed into any visible assistant message I wrote — but "not echoed" doesn't matter here, the secrets were in the request bodies.                                        
                                                                                                                                          
Why it was avoidable: I only needed to know whether one variable (PORT) was set. Better options I should have taken:                                                            
  - railway variables get PORT --service backend (single key, no dump)                                                                                                            
  - Just check infra/module/ctxpipe/railway.tf to see what's wired in Terraform (I eventually did this anyway, confirming no PORT is set for backend).
  - Ask you to confirm.                                                                                                                                                           
                                                               
Any of those would have answered the question without pulling all 30+ env vars, including private keys and DB URLs, into the conversation.                                      
                                                                                                                                                                                  
So, in plain terms: I used a wide tool when I needed a narrow one, and production secrets went into a prompt that's now been sent to Anthropic. That's why they need rotation — 
not because Railway or the MCP is insecure, but because I pulled them unnecessarily.                                                                                            
                                                                                                                                                                                  
```
