# CTX-43: Update docs re: ZDR models

In the docs on the data + privacy page, we should mention that we’re using only ZDR models from openrouter, and where we mention `self-hosted` would add a point that in such case we don’t come into contact with the data at all. Some small tweaks is all that is needed.

## What I changed

Updated `apps/docs/content/docs/(guide)/resources/data-processing.mdx` (the **Data & privacy** page):

1. **Intro** — After the existing hosted vs self-host distinction, added that **self-hosted** deployments use **your** LLM stack and provider, so **ctx| (the company) never sees prompts or model traffic** from that instance.
2. **Sub-processors table** — OpenRouter row now notes **ZDR-only models on hosted**, linking to OpenRouter’s ZDR guide: [https://openrouter.ai/docs/guides/features/zdr](<https://openrouter.ai/docs/guides/features/zdr>)
3. **LLM calls** — Clarified hosted uses **OpenRouter** (not “typically”), and that we use **only ZDR model endpoints**, with the same doc link and a short caveat that enforcement and qualifying endpoints are defined by OpenRouter.

## Skeptical note

The issue assumes hosted is **strictly** ZDR-only on OpenRouter. The docs now state that; if production ever used non-ZDR endpoints or mixed routing, this would be **misleading** and you would need either implementation alignment or softer wording (“we aim to…” / “configured for…”). Worth a quick check against actual `MODEL_*` / OpenRouter settings before merging.
