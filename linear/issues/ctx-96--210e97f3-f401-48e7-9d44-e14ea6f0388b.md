# CTX-96: SSE error in chat

Chat responses is taking far longer than expected, both in Chat page and 'Ask' panel in the knowledge graph UI.

Once the chat HAS ended with a response, this error appears in the UI (only in the KG 'Ask' chat UI):
Received text-end for missing text part with ID "gen-1777598603-8V6VBXmV4sDi5zE90ET6". Ensure a "text-start" chunk is sent before any "text-end" chunks.

The chat's streaming is stilted, with significant pauses during the response.

Not sure what Railway backend logs are available, so ask for evidence as needed.

## Diagnosis

The error comes from the AI SDK UI stream processor: it requires every `text-delta` / `text-end` to follow a `text-start` for the same `id`. Our backend wraps the LangGraph stream with `filterInternalNodeMessageChunks`, which **drops whole** `messages` events for internal nodes (`planner`, `conversationNaming`). That can remove the chunk that would have emitted `text-start` while a later chunk from the visible agent still emits `text-delta` / `text-end` for the **same** message id — so the client sees `text-end` with no open text part. That matches *"Received text-end for missing text part with ID …"*.

The KG **Ask** panel felt worse partly because it runs `matchKnowledgeGraphNodes` on **every** `messages` change while streaming (throttle was only 700ms between *successful* focus updates, not between effect runs).

## What I changed

1. **Backend** — `createTextStartRepairTransform()` after `toUIMessageStream` (with Vitest coverage): if a `text-delta` or `text-end` arrives for an id with no `text-start` yet, enqueue a synthetic `text-start` first (same pattern as the existing tool-invocation repair).
2. **UI** — KG Ask panel: **400ms debounce** on the streaming auto-focus effect so we do not scan the graph index on every token.
