# CTX-65: Add logo to MCP

Now that the MCP is fixed for CodeRabbit - it's missing a logo reference, so when it is added it shows a default placeholder instead of the ctx| brand logo.

## What was wrong

CodeRabbit was showing the default globe because our MCP `initialize` response only advertised `name` + `version`. The MCP spec’s `Implementation` type also supports `icons` (and related display fields); without them, UIs fall back to a placeholder.

## What I changed

1. `McpServer` now uses full `Implementation` metadata via `getMcpServerImplementation()` — `title: "ctx|"`, `websiteUrl` from `AUTH_BASE_URL`, and `icons` with:
   * an **SVG data URI** (built from the same mark as `apps/ui/src/components/Logo/logo.svg`), and
   * a **same-origin HTTPS URL** as a fallback for clients that only load remote images.
2. **Public asset route** — `GET /.well-known/ctxpipe/mcp-brand-logo.svg` serves the SVG with `Cache-Control` (no auth).
3. **Docker** — `apps/backend/public/` is copied into the backend image so that path exists in production.
4. **Tests** — `mcp-brand-asset.test.ts` asserts the SVG is served; `mcp.test.ts` now sets `AUTH_BASE_URL` in the test env stub.

Branch: `cursor/mcp-brand-logo-f3c2` — **PR:** [https://github.com/ctxpipe-ai/ctxpipe/pull/116](<https://github.com/ctxpipe-ai/ctxpipe/pull/116>)

**Caveat:** If CodeRabbit’s UI ignores `icons` entirely, you would still see the placeholder; that would be a client limitation, not something we can fix server-side. The change aligns with the MCP SDK’s `Implementation` schema, so any client that implements icons should pick this up after the deploy. Re-connect or refresh the MCP server entry in CodeRabbit after release to pick up the new `initialize` payload.
